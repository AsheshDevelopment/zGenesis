Build and update the final client from the repository root:

```powershell
.\build-htlauncher.bat
# Optional: .\build-htlauncher.bat -Configuration Debug -Parallel 4
```

This builds the launcher and stages its required assets/runtime into `_client`,
overwriting `HTLauncher.exe` and preserving `userdata`. Close the client first.
The same command works from any working directory when invoked by its full path.

## Configure

    cmake -S . -B build -DTANTRA_CLIENT_ROOT="C:/_GitHub/TantraSrc/TantraClient" -DTANTRA_DATA_ROOT="B:/__TANTRA/TantraDataScripts"

If an OGRE SDK is installed, provide its CMake package location:

    cmake -S . -B build -DOGRE_DIR="C:/path/to/ogre/CMake"

For the supplied 64-bit SDK, configure with the x64 generator:

    cmake -S . -B build-ogre-x64 -A x64 -DOGRE_DIR="C:/Users/Ashesh/Downloads/OGRE/ogre-sdk-v14.6.1-msvc142-x64/CMake"
    cmake --build build-ogre-x64 --config Debug
    cmake --build build-ogre-x64 --config Release

The supplied SDK contains release OGRE binaries only. When
`TANTRA_OGRE_DEBUG_USE_RELEASE_ABI` is enabled (the default), Debug builds keep
Debug application settings but use the SDK's release OGRE/CRT ABI so they can
link and run with that SDK. A custom OGRE build with debug libraries can disable
this option.

The supplied OGRE source tree is recorded as OGRE_SOURCE_ROOT for future
custom OGRE builds. The current remake links the prebuilt x64 SDK because it
already contains the matching headers, import libraries, plugins, and runtime
DLLs; the full OGRE source is not copied into this project.

The SDL3 source checkout under `external/SDL3` supplies the application window
and event loop when `TANTRA_USE_SDL3=ON`. OGRE receives SDL3's native Win32
window handle and remains the renderer. A source-built OGRE profile can be
selected with `OGRE_DIR` pointing to `ogre-rts-install/CMake`; it includes the
matching Direct3D11 runtime and explicit HLSL materials for manual objects.

Type-2 character previews use the explicit TMB influence-group mapping to
cover every render vertex, including UV seam duplicates. See
[mapping evidence](../../reference/assets/TMB_VERTEX_INFLUENCE_MAPPING.md). Full visual parity remains unverified; the backend now uses
[authored bind matrices](../../reference/assets/AUTHORED_BIND_SKINNING.md).

The intro logo and login panel now use native pixel sizes and viewport anchors
from `HTIntroManager.cpp`, with a dedicated screen-space shader. The
1024x512 logo is centered and the 512x256 login texture starts at
`(screenWidth/2 - 150, screenHeight - 400)`. Resizing preserves their pixel
dimensions. Native message-catalog labels now use the source locale font,
integer placement and two shadow passes, remaining hidden until camera
completion. See [login presentation and pending controls](../../reference/presentation/NATIVE_LOGIN_PRESENTATION.md).
Login now accepts committed text with native focus/Tab/Escape/Backspace,
password masking, original button states, saved ID and deferred Cancel.
The [control evidence and limits](../../reference/presentation/NATIVE_LOGIN_CONTROLS.md) distinguish this
from unfinished authentication, full IME and complete native UI rendering.
User data defaults to `userdata/system/SaveID.bin` beside the executable;
`--user-data-root` selects another remake-owned directory. `--asset-gallery`
enables the separate six texture preview icons.

The default intro uses the supplied source login camera profile. Asset-gallery
mode retains the diagnostic camera and character/item/effect previews, while
default intro logs missing source object meshes without displaying placeholder
markers. Terrain and map objects share an uncentered positive-coordinate world
origin; exact terrain spacing and native camera projection parity remain open.

Normal startup renders the logo before intro map submission, hides it when

## Asset policy

TantraClient is never modified. Generate a manifest with:

    .\tools\scan-client-assets.ps1

The client manifest includes an explicit category (Texture, Mesh, Animation,
Package, Effect, Audio, MapConfig, or Other) and source profile. Use -Profile Global
or -Profile K3 when scanning a selected revision; unknown extensions remain in
Other until a format reader is verified.

Generate the Excel/XML data manifest with:

    .\tools\scan-data-sources.ps1

Derived OGRE resources belong under derived-assets and must retain the original
relative path and SHA-256 provenance.

Stage the minimal OGRE runtime DLL/configuration set with:

    .\tools\stage-ogre-runtime.ps1

Create a reproducible x64 runtime package with:

    .\tools\package-remake.ps1

The package contains only the remake executable, required OGRE runtime files,
derived Intro/UI/character resources, and a SHA-256 package manifest. It also
contains `DERIVED_PROVENANCE.tsv`, which records the canonical source
archive/file, source hash, entry name, derived hash, and extraction status for
each first-slice derived resource.

Run the repeatable two-cycle runtime check with:

    .\tools\verify-runtime-smoke.ps1

The smoke check also performs a graceful auto-exit cycle. To verify a specific
Direct3D11 adapter, pass its exact name with `-RenderDevice`.

Run the packaged executable against the canonical client source with:

    .\package\x64\Release\run-remake.ps1

The launcher sets `TANTRA_CLIENT_ROOT` to the canonical client path and uses
the package-local `intro`, `ui`, `character`, and `effects` derived-resource folders.
Override `-ClientRoot`, `-DerivedRoot`, `-UiRoot`, `-CharacterRoot`, or `-EffectRoot` when
testing another read-only source profile.

The executable also accepts deterministic command-line overrides such as
`--client-root <path>`, `--derived-root <path>`, `--ui-root <path>`,
`--character-root <path>`, `--effect-root <path>`, `--sound-root <path>`, `--capture <path>`,
`--audio 1`, `--no-terrain`, `--diagnostic-only`, and
`--render-device <name>`. `--auto-exit-frames <n>` provides a deterministic
graceful-shutdown hook for automated runtime checks.

Normal intro startup enables audio and resolves BGM 30015 from the original
catalog before showing the logo. The supplied catalog selects
`Japan_Battle_Final.mp3`, with two plays at the source stream-volume request.
Use `--audio 0` or `TANTRA_ENABLE_AUDIO=0` to mute it. Gallery/diagnostic modes
default to disabled audio. Backend failures emit diagnostics. See
[source order and real playback verification](../../reference/presentation/NATIVE_INTRO_MUSIC.md).

The gate monsters now resolve their original seven motion samples from
`MONSound_K1.hpk`. Initial WLK/RUN starts are silent as in the source; later
animation changes immediately issue the selected samples, including the original
ATK2/skill random calls and finite repetition counts. SDL3 decodes the WAVs;
x64 spatial output receives native camera-relative positions, distances and
volume. Explicit audio muting covers these samples too. See
[motion sound evidence, runtime checks and remaining acoustic limits](../../reference/presentation/NATIVE_INTRO_MOTION_SOUNDS.md).

The gate fire now resolves through the original Map/FX catalogs into its exact
MonsterEtc TFX graph. Both emitter records, authored keys and textures are decoded
and staged. The original looping mode-2 fire and smoke now run in the default
intro after model animation updates, with native activation, visibility, unit
conversion, curves and blend states. See
[native fire resource graph](../../reference/presentation/INTRO_FIRE_RESOURCE_GRAPH.md).
The [native particle math component](../../reference/presentation/NATIVE_PARTICLE_MATH.md) now covers the
selected mode-2 CPU rules and curves; the
[runtime report](../../reference/presentation/NATIVE_INTRO_FIRE_RUNTIME.md) records its OGRE integration,
native evidence, captured result and remaining limits. At that earlier fire
checkpoint, Debug/Release CTest coverage was 57 checks each. This does not
complete the full remake.

The source-confirmed Intro THM heightfield is enabled by default. Set
`TANTRA_ENABLE_TERRAIN=0` to isolate the renderer shell while diagnosing a
terrain-specific issue.

For an opt-in visual capture, set `TANTRA_CAPTURE_PATH` to a `.bmp` path before
launching. The first rendered client frame is written as a 32-bit BMP for
manual parity review.

The packaged capture check can be run with:

    .\tools\verify-runtime-capture.ps1

## Current milestone

The initial implementation provides a CMake project, configurable external
source roots, read-only original-client verification, asset manifest generation
with SHA-256 hashes, a C++ asset probe suitable for CTest, and an optional OGRE
backend with root, scene manager, camera, clean shutdown, a standalone x64
Win32 executable, Map_Intro.cfg parsing, and the first original bitmap texture
rendered through an OGRE material. It also parses and renders the original
Intro rigid sky and SkyTerrain TMD meshes with an explicit source-coordinate
scale, and indexes the Intro TerrainTex.hpk archive without modifying it. The
two sky TGA payloads and SkyTerrain DDS payload are extracted into ignored
derived-assets/intro output and registered as an OGRE resource root during the
remake build. The first Intro UI bitmap is also extracted from INTROUI.hpk and
rendered as a facade-owned UI sprite.
The first bounded item TMB probe and render path is included for
ITEM_Fallen_Gem_01.tmb.
Application playback uses monotonic elapsed seconds through
`renderOneFrame(deltaSeconds)`, independently of render rate. Tooling can pass
an explicit timestep; the no-argument call advances a fixed 1/30 second. A
source-animation test compares two seconds of playback at 30/60/144 updates
per second and verifies fractional loop remainders.

The original PC_Asura_Basic.tmb geometry is also submitted as a bounded
character mesh slice, and the renderer facade exposes normalized screen-space
object picking. The original ASURA idle TAB position/quaternion tracks are
decoded and sampled deterministically; the renderer applies the
`Pelvis_control` track to the multipart rigid character nodes and updates the
decoded multipart TMB geometry through a dynamic weighted preview. Type-2 TMB
meshes now expose validated header, material, bone, influence-count, and
multipart geometry metadata. Character hierarchy now comes from the validated
TMB child-count tree, replacing the earlier name-based parent guesses. Stored
affine bone matrices are retained; native inverse-bind and remaining attachment
semantics are unresolved. See [skeleton format evidence](../../reference/assets/TMB_SKELETON_TREE.md).
The Intro TFX container is validated before a
bounded deterministic effect billboard is animated from its original texture
reference; full particle emitter graphs remain unsupported.
It also records the external Excel/XML data source as a separate provenance
root instead of mixing authored tables with shipped client assets.
The map resource probes also decode the native TCC cell grid and verify the
1024x1024 Jina1st collision/state fixture without modifying the client files.
The Intro THM height/normal samples are also decoded and submitted as an OGRE
heightfield using the source 10-unit cell spacing and coordinate scale. Its
source section-weight metadata is retained, and the original `section0.dds`
and `detail.dds` payloads are extracted into the derived Intro root and used
by the explicit D3D11 terrain material when available.

Format-specific map, mesh, animation, texture-package, and effect importers
remain separate milestones. Unknown formats must be recorded rather than
silently guessed.

The source-driven single-mesh monster texture replacement bridge and its
verification limits are documented in [monster texture replacement](../../reference/assets/MONSTER_TEXTURE_REPLACEMENT.md).

Animation duration and sampling now use [authored TAB timestamps](../../reference/assets/AUTHORED_ANIMATION_TIMING.md),
with native binary evidence and explicit remaining integration limits.

The skinned facade now exposes finite `startSkinnedObjectAnimation` and
`getObjectAnimationState`; see [source behavior and remaining integration](../../reference/assets/FINITE_ANIMATION_PLAYBACK.md).

[Native pose interpolation and STOP rendering](../../reference/assets/NATIVE_ANIMATION_POSES.md)
documents the scalar spherical interpolation port and the corrected alpha-one
STOP draw rule. The implemented zero-play-time [ChangeAnimation component](../../reference/assets/NATIVE_CHANGE_ANIMATION.md)
uses local blending and authored bind matrices; complete intro integration remains unfinished.

The skinned backend now uses [authored TMB bind matrices](../../reference/assets/AUTHORED_BIND_SKINNING.md)
and raw weights. `--asset-gallery --inspect-character` provides an isolated
visual diagnostic; complete model/scene parity remains unverified.
